Every string your app shows, in one typed catalog.

UX writers keep a product's words in one document, the copy deck. prosebook makes it the source of truth: each string lives in YAML with the context a translator needs, and the code holds only keys.

cart.items:
  kind: state
  surface: status
  context: Under the cart heading, counts what is in the cart.
  args:
    count: how many items are in the cart
  en: '{count, plural, =0 {Your cart is empty.}

What you get

Words you can change without touching code, checked like code.

prosebook generate compiles the catalog into typed modules, one per locale. Everything a parser would do in the browser happens at build time instead.

Typed

A missing key, a misspelled key or a missing argument is a type error. Completing a key shows its English text and context.

Compiled

Each message, in ICU MessageFormat or MessageFormat 2, becomes a plain function. No parser ships, no eval.

Checked

Placeholders that drift between the source and a translation fail the build. A translation whose source changed is marked stale.

Pruned

A Vite, Next.js or Bun build ships only the messages the code names, and fails on a read whose key it can't see. Keys built from data still count.

Split

With Vite, Bun or Next, each area's messages ship beside the code that reads them, so a lazy route brings its own, already in the reader's language on its first render.

Written well

An optional lint holds the words to a writing guide: word budgets per kind, periods, sentence case, banned filler, and {count} files outside a plural, in the source and its translations. Plugins add your own rules, scoped by kind, surface and locale. Guidelines no rule can check go in a generated WRITING.md, for your coding agent to read before it writes.

Extracted

prosebook extract moves hardcoded JSX text into the catalog, whole sentences with their links, and rewrites the component.

In context

In dev, Alt-click any string to open its entry, or Alt-right-click to edit it on the page, or to leave a comment or a mark for removal for your coding agent. The page updates without reloading.

Any framework

React, Preact, Vue, Svelte and Solid each get a binding that updates what reads a message when the locale changes, and turns tags into their own elements, snippets or slots.

Native too

The same catalog generates Rust, Swift and Kotlin for a tray, a menu bar or a CLI, with plurals, numbers and dates that say what the browser says, and the string resources Android and Apple read.

No keys in the DOM

In dev the runtime reports each string it hands out, and the text under the pointer is matched back to it. t(), <Text>, rich sentences and attributes all work.

Edits keep your place

Saving a catalog or translation swaps that locale's messages in place. The page keeps its locale, its state and your scroll.

Your editor, or none

Alt-click opens the entry through Vite's own /__open-in-editor. Alt-right-click edits it in a dialog on the page, as fields or as YAML, checked before it's written. Lint's findings show under each text as you type, with a fix where there is one. A comment or a mark for removal goes into the entry, for the next edit, or your agent, to act on.

For translators

Know what changed since the last translation.

  • Only text to translate. A locale file holds key: translation; the context stays in the catalog.
  • Stale, automatically. copy/lock.json records the source each translation was made from, and shows the change as a word diff.
  • Fallback, key by key. A missing key falls back through its parents (pt-BR → pt) to the source.
  • Any model, checked. prosebook todo de --prompt writes the prompt for the model you use, and prosebook import checks its reply before a word is written.
  • Any translation tool. prosebook export de de.xlf writes XLIFF 2.0 or JSON with each entry's context, and import takes the tool's file back the same way.
